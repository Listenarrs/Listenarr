# Automatic book identity policy

`CorroboratedAutomaticV1` assesses every returned search candidate and passes every
candidate to the existing quality engine. Automatic selection requires a confirmed
identity and a nonrejected, positive quality score. Both search-and-download and
the scheduled worker, including its author-free fallback, use the same service.

A complete supported title with a complete credited author can confirm a work.
Structured provider authors and complete release-name credits are supported;
an inferred `Artist` is not an independent author fact. Display placeholders such
as `Unknown Author` cannot corroborate a title. Only explicitly verified,
candidate-specific identifiers can confirm without author evidence, and reliable
contradictions prevent confirmation.

Exact title-only candidates remain scored and visible for explicit manual choice.
Unverified aliases, surnames, omitted middle initials, arbitrary subtitle prefixes,
bundles, and unexplained extra text defer automatic selection. This is deliberate
and applies equally to short and long titles. Existing profile constraints still
control format, size, language, and other quality preferences.

The interpreter protects a complete reference title before interpreting surrounding
credits or annotations. It does not delete title words or infer identity from token
overlap. A separately stored subtitle supports a main-title form; punctuation alone
does not establish that relationship. Unknown future layouts defer. Provider facts
can still be inaccurate; confirmation is an evidence policy, not proof of audio
contents.

`identity-policy-v1.json` retains 205 controlled scenarios and 210 candidate
observations, including original fixture fields and legacy expectations. Its
`expectedConfirmed` values were explicitly adjudicated under this policy, not
generated by the matcher. Identity confirmation does not override quality rejection.
The feature tests additionally assert statuses, preservation of literal titles,
provenance, identifier assurance, generated layouts, cancellation, source changes,
fresh target/profile validation, quality association, and deterministic selection.

Run the focused policy tests with:

```powershell
dotnet test tests/Listenarr.Tests.csproj -c Release -p:SkipFrontendBuild=true --filter 'FullyQualifiedName~Listenarr.Tests.Features.Application.Search.Matching'
```

No schema migration, title allowlist, new catalogue request, or change to explicit
manual download authorization is required. The existing `SearchResult.Score`
remains the quality score; identity and reasons are separate diagnostics.
